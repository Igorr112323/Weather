# Аудит готовности AgroCast к продакшену

Дата: **2026-09-05, UTC**. База анализа: `47840cb1edcfcd66b4f90185e3e7a3829c01c3d5`.

[План работ](PLAN.md) · [Критерии выпуска](RELEASE_CHECKLIST.md)

## Вывод

**Проект — работающий исследовательский MVP, но пока не готов к открытому промышленному использованию.** Есть полноценный расчётный путь, интерфейс, тесты, Docker и CI. Основные препятствия — не отсутствие новых моделей, а безопасность, сохранность состояния, актуальность входов и достоверность процедуры оценки качества.

Особенно важно: успешный мини-аудит воспроизводит текущую реализацию проверки, но не доказывает независимый walk-forward-навык. Ниже установлены использование будущей информации, переиспользование наблюдаемых классов между точками и различия между LIVE и аудитом. Это **не доказывает отсутствие полезного сигнала**; это означает, что публичные оценки навыка надо пересчитать исправленным способом.

В рамках первоначального аудита изменялась только документация; на указанном выше базовом коммите перечисленные дефекты ещё не были исправлены. Рабочие данные и обученные артефакты не перезаписывались. Последующие изменения отражены в [прогрессе реализации](PROGRESS.md); доказательства и ссылки на строки ниже относятся к исходному срезу, а не к уже изменённому коду.

- Проверка зависимостей через `pip check` и `pip-audit`.

Среда: Python **3.11.2**, Linux, 2 vCPU, около 3.8 GiB RAM. Из незакреплённых зависимостей установились FastAPI 0.141.1, Pydantic 2.13.5, Uvicorn 0.52.4; pytest 9.1.1.

Выводы о конфигурации контейнера получены чтением файлов, а не запуском образа.

## Реестр проблем

Приоритет **P0** блокирует публичный релиз соответствующей функции. **P1** обязателен до стабильного промышленного выпуска. **P2** — улучшение после безопасного пилота. «Проверено» ниже означает воспроизведённое поведение; «по коду» — установленный путь исполнения, без полноценного эксплуатационного испытания.

### R01 · P0 · Нет контроля доступа к изменению данных и расчётам

[product.py:117–195, 265–281](../../AgroCast/agrocast/serve/product.py#L117-L195), [api.py:83–113](../../AgroCast/agrocast/serve/api.py#L83-L113), [Caddyfile](../../deploy/Caddyfile).

**Проверено:** анонимные `POST /api/crops` и `DELETE /api/crops/{name}` возвращают 200 и меняют БД. В OpenAPI нет security schemes. У `prepare`, `subscribe`, `region/refresh` нет аутентификации или квот; альтернативный API также открывает `/update`.

**Последствие:** любой посетитель при публичном размещении может менять общий справочник и инициировать дорогие операции. Нужны роли, владение ресурсами и ограничения нагрузки. HTTPS не заменяет авторизацию.

### R02 · P0 · Сохранённый пользовательский текст попадает в HTML без экранирования

[crops/db.py:71–105](../../AgroCast/agrocast/crops/db.py#L71-L105), [index.html:249–263](../../AgroCast/static/index.html#L249-L263), [report.html:101–103, 300–321](../../AgroCast/static/report.html#L300-L321).

**Проверено:** без авторизации сохранены и прочитаны поля `name`/`breeder` с безвредной HTML-разметкой. **По коду:** они конкатенируются в `innerHTML`; туда же попадают имена полей и сообщения задач. Это путь для stored/DOM XSS. Выполнение вредоносного JavaScript в браузере не проводилось.

**Исправление:** безопасные DOM-операции и `textContent` для текста, явные разрешённые шаблоны, CSP как дополнительная защита, браузерные регрессионные тесты.

### R03 · P1 · HTTP-контракты допускают ошибочные запросы и неверный кэш

[product.py:82–101, 198–200, 265–281](../../AgroCast/agrocast/serve/product.py#L82-L101), [region.py:31–34](../../AgroCast/agrocast/serve/region.py#L31-L34).

**Проверено:** `start=invalid-month`, `horizon=-9`, `season_len=0`, произвольные `mode` и `kind` вместе приняты `/api/prepare` с 200 и переданы в запуск задачи. Внутри обычного forecast горизонт ограничивается, но это не заменяет валидацию остальных параметров и hindcast.

Свежий файл региона для октября 2026 возвращает `fresh=true` на запрос марта 2027: ключ не учитывает `start`. `SubscribeRequest.start_month` принимается, но не сохраняется. Удаление сорта с `/` в имени даёт 404 даже при URL-кодировании.

**Исправление:** диапазоны, конечные числа, enum, даты, допустимые сочетания параметров, ID вместо имени в CRUD, версионируемый ключ кэша.

### R04 · P0 · Задачи не переживают рестарт и не имеют общей очереди

[product.py:53, 122–131, 248–281](../../AgroCast/agrocast/serve/product.py#L248-L281), [pipeline.py:249–307](../../AgroCast/agrocast/serve/pipeline.py#L249-L307), [region.py:165–182](../../AgroCast/agrocast/serve/region.py#L165-L182).

**По коду:** `JOBS` живёт в памяти одного процесса; работы выполняются daemon-потоками, региональная работа создаёт свой `ProcessPoolExecutor`. Нет общего лимита активных работ, дедупликации, deadline, отмены или очистки завершённых результатов.

**Последствие:** рестарт теряет статусы и адресуемые отчёты, несколько Uvicorn workers видят разные задачи, повторные запросы размножают вычисления. Простое увеличение `--workers` проблему не решает.

### R05 · P0 · Production-состояние частично находится вне persistent volume

[pipeline.py:27–40](../../AgroCast/agrocast/serve/pipeline.py#L27-L40), [product.py:164–169](../../AgroCast/agrocast/serve/product.py#L164-L169), [orchestrator.py:540–555](../../AgroCast/agrocast/forecast/orchestrator.py#L540-L555), [docker-compose.yml](../../deploy/docker-compose.yml).

**По коду:** для точек внутри world-box конфигурация указывает на `world`; прогнозы и подписки пишутся в `world/registry.sqlite`, live ledger — в `world/artifacts`. Compose сохраняет только `/app/data`. Пересоздание контейнера не сохранит эти изменения в `/app/world`.

[ZarrStore.write:32–51](../../AgroCast/agrocast/store/zarrstore.py#L32-L51) удаляет старый каталог до переименования нового; имена временных файлов общие. JSON и Parquet также перезаписываются без общего протокола публикации. Сбой или конкурирующие writers могут оставить отсутствующее/неполное состояние.

### R06 · P0 · Актуальный прогноз выдаётся на устаревших предикторах

[dataset.py:261–349](../../AgroCast/agrocast/features/dataset.py#L261-L349), [orchestrator.py:263–273, 338–372](../../AgroCast/agrocast/forecast/orchestrator.py#L263-L273).

**Проверено на 2026-09-05:**

| Набор | Последняя временная метка | Возраст метки | Лимит текущего скрипта |
|---|---|---:|---:|
| `daily_region` | 2026-08-28 | 8 дней | 14 дней |
| `sst` | 2026-07-15 | 52 дня | 120 дней |
| `fields_monthly` | 2026-02-01 | **216 дней** | **60 дней** |
| `strat_snow` | 2026-02-01 | **216 дней** | **60 дней** |
| `oisst_boxes` | 2026-07-01 | 66 дней | 90 дней |
| `regimes` | 2026-02-01 | 216 дней | 365 дней |
| `soil_monthly` | 2026-08-01 | 35 дней | Не проверяется |

После `dropna()` общий predictor frame заканчивается **2026-02**, хотя суточные наблюдения новее. LIVE на октябрь использует февраль и сезонную модель с `lead=1`. Фактическая заблаговременность и проверенный горизонт расходятся; свежесть суточных данных этого не исправляет.

**Исправление:** отдельные `issued_at`, `data_cutoff`, `available_at`, `target_start/end` и фактический lead; запрет выдачи неподдерживаемого прогноза либо явно маркированный проверенный fallback.

### R07 · P0 · Healthcheck не определяет готовность сервиса

[product.py:301–314](../../AgroCast/agrocast/serve/product.py#L301-L314), [Dockerfile:17–18](../../Dockerfile#L17-L18), [zarr_freshness.py:27–84](../../AgroCast/scripts/zarr_freshness.py#L27-L84).

**Проверено:** `/api/health` возвращает 200 и `ok=true` как со старыми данными, так и с корректным `config.json`, но без всех Zarr-наборов. Docker смотрит только на HTTP 200.

Скрипт свежести пропускает отсутствующие Zarr; при отдельно успешной региональной проверке завершится с кодом 0. Региональные артефакты оцениваются по `mtime`, которое обновляется после checkout, а не по дате их выпуска. Ошибки региональной проверки только печатаются. Scheduled Actions проверяет Git-снимок, не действующий production volume.

**Исправление:** раздельные liveness/readiness, 503 при отсутствии обязательных ресурсов, валидированный manifest и мониторинг работающего окружения.

### R08 · P0 · Временная изоляция обучения нарушена на нескольких уровнях

- [pipeline.py:183](../../AgroCast/agrocast/serve/pipeline.py#L183) и [audit_full.py:163](../../AgroCast/scripts/audit_full.py#L163): `rec.year != Y` оставляет **будущие** годы при подборе весов для года Y. В поставленных записях есть годы 2004–2026. LOYO не равен последовательному walk-forward.
- [dataset.py:214–242](../../AgroCast/agrocast/features/dataset.py#L214-L242): SST EOF/PCA и нормировки рассчитываются по фиксированной базе до 2020 года, включая будущее для ранних исторических выпусков.
- [training_data:397–435](../../AgroCast/agrocast/features/dataset.py#L397-L435): отсечение проверяет начало сезонной цели, а не её конец. **Контрпример выполнен:** при cutoff `2020-12` в train попал сезон `2020-12…2021-02`.
- [nn_stack.py:69–101](../../AgroCast/agrocast/blend/nn_stack.py#L69-L101): общий alpha выбирается с использованием 2015–2024, после чего используется и при оценке этих лет. Нужна вложенная временная валидация.

**Исправление:** as-of контекст на всём пути, train только по уже доступным завершённым целям, embargo для пересекающихся сезонов, fit признаков и всех postprocessors внутри соответствующего fold. Регрессионный принцип: изменение данных после cutoff не меняет более ранний прогноз.

### R09 · P0 · LIVE, hindcast, refit и audit — разные системы

[orchestrator.py:155–197, 344–355](../../AgroCast/agrocast/forecast/orchestrator.py#L155-L197), [pipeline.py:138–246](../../AgroCast/agrocast/serve/pipeline.py#L138-L246), [audit_full.py:225–299](../../AgroCast/scripts/audit_full.py#L225-L299), [refit_world.py:72–94](../../AgroCast/scripts/refit_world.py#L72-L94).

LIVE применяет regime climatology, shrinkage, conformal и ocean-spread correction; в hindcast/мини-аудите путь другой. Hindcast возвращает некалиброванные Q, а аудит отдельно измеряет Q с загруженным conformal. Monthly-аудит ограничивается `lead=1`, тогда как API выдаёт несколько горизонтов. `refit_world` использует безусловную изотонику вместо gate из обучения точки.

**Проверено:** сезонный backtest Parquet содержит 9 моделей без `phys_djf`/`phys_mam`, а LIVE включает обе физические модели. Значения alpha текущих артефактов — seasonal t2m 0.0, monthly t2m 0.2. LIVE читает alpha непосредственно из JSON, обходя запрет tp в `load_alpha`; текущий tp alpha равен нулю, но гарантия не закреплена в едином inference-пути.

**Исправление:** один исполняемый pipeline для выпуска и оценки, совместимый manifest моделей, единый набор guards и тесты паритета для каждого разрешённого горизонта.

### R10 · P0 · Пространственный аудит не проверяет локальные наблюдаемые классы

[audit_full.py:147–165, 270–298](../../AgroCast/scripts/audit_full.py#L270-L298), [audit_full.py:453–488](../../AgroCast/scripts/audit_full.py#L453-L488).

**Проверено на mini5:** во всех **960** сочетаниях mode/variable/year/month у пяти точек одинаковые `obs_tercile` и `obs_z`, хотя физические `fact` различаются. Сезонные вероятности t2m между точками тоже идентичны. Это следует из использования общих записей backtest вместо локального факта для RPS/hit/coverage.

Поэтому 4800 строк нельзя трактовать как 4800 независимых пространственных проверок навыка. Обычный Wilson interval по всем повторяющимся строкам не учитывает пространственную и временную зависимость.

**Исправление:** наблюдения, климатология и терциль конкретной ячейки; отдельные региональные и точечные baseline; доверительные интервалы с блоками по времени/пространству; раскрытие фактического числа независимых блоков.

### R11 · P0 · Покрытие и ECE не подтверждают заявленные гарантии

[conformal.py:44–88](../../AgroCast/agrocast/blend/conformal.py#L44-L88), [ledger.py:186–191](../../AgroCast/agrocast/skill/ledger.py#L186-L191), [audit_full.py:229, 475–483](../../AgroCast/scripts/audit_full.py#L475-L483), [test_conformal.py:32–43](../../AgroCast/tests/test_conformal.py#L32-L43).

Conformal-поправки оцениваются обычным `np.quantile`, без явной конечновыборочной поправки ранга. В ledger калибровка обучается и оценивается на одной выборке; аудит загружает общий готовый calibrator. Имеющийся тест покрытия тоже оценивает обучающую выборку. Это не является доказательством out-of-sample покрытия или безусловной 80%-гарантии на зависимом климатическом ряду.

ECE в `audit_full` группируется по фактическому классу, в ledger — по уверенности прогноза. **Проверено:** для специально построенного идеально калиброванного примера ledger ECE ≈0, audit ECE **0.3613**. Числа с одинаковым названием имеют разную интерпретацию.

**Исправление:** независимые временные calibration/test блоки, обоснованный алгоритм интервалов, единая спецификация метрик, интервальные оценки по сегментам. До этого 79–80% следует называть результатом текущей проверки, не гарантией.

### R12 · P1 · Реестр не обеспечивает заявленную неизменяемость и происхождение

[ledger.py:49–55, 280–313](../../AgroCast/agrocast/skill/ledger.py#L280-L313), [orchestrator.py:540–555](../../AgroCast/agrocast/forecast/orchestrator.py#L540-L555).

**По коду:** от SHA-256 сохраняются 16 hex-символов. Хэш охватывает округлённые выходы и часть контекста, но не target, входной снимок, версии модели и кода. Повторный выпуск заменяет совпавшую запись, весь Parquet переписывается. Автоматически фиксируются только первая сезонная цель и не monthly-выпуски.

Хэш сам по себе не доказывает время публикации и не защищает от пересчёта хэша вместе с записью. Нужны уникальные неизменяемые выпуски, полный digest входов/артефактов и, если обещана проверяемая подлинность, отдельный механизм подписания/временной фиксации.

### R13 · P0 для агрорекомендаций · Есть ошибка единиц и нет общего запрета непроверенных советов

[insight.py:212–236](../../AgroCast/agrocast/agro/insight.py#L212-L236), [advisor.py:20–39](../../AgroCast/agrocast/agro/advisor.py#L20-L39), [orchestrator.py:372–399](../../AgroCast/agrocast/forecast/orchestrator.py#L372-L399).

`usable` измеряется в мм. Для сухого сценария используется `(ETc − P) × 10 − usable`, для медианы — `(ETc − P − usable) × 10`. В первой формуле смешаны мм и м³/га; расхождение при положительном дефиците равно `9 × usable` м³/га.

Совет по поливу в `advisor` зависит от прогнозных осадков и их вероятностей без проверки `no_skill`. Водный баланс также использует прогнозные осадки. Утверждение README «полив не на прогнозе осадков» этим путям не соответствует. Сезонная температура одинаково раздаётся всем месяцам, осадки делятся поровну; пригодность полученных суточных сценариев для дат сева/морозов отдельно не доказана.

**Исправление:** тесты размерностей, единый policy допуска советов, проверенная сезонная дезагрегация и экспертная валидация. До неё — сценарная оценка с ограничениями либо отключение конкретного совета.

### R14 · P1 · Верификация опубликованных прогнозов неполная и неидемпотентная

[cycle.py:49–101](../../AgroCast/agrocast/autopilot/cycle.py#L49-L101), [registry.py:66–72](../../AgroCast/agrocast/ingest/registry.py#L66-L72), [climatology.py:9–21](../../AgroCast/agrocast/features/climatology.py#L9-L21).

**По коду:** сезон оценивается, если доступен хотя бы один его месяц; повторный цикл снова вставляет scores без unique key. Месячная агрегация не проверяет полноту дней, а `sum()` осадков может выдать 0 для полностью пустой группы. Это может искажать факты, веса и отчётность.

**Исправление:** политика полноты наблюдений, отдельный статус pending verification, уникальный ключ оценки, повторяемый upsert и версионирование исправленных фактов.

### R15 · P1 · Обновления и артефакты не имеют единого жизненного цикла

[cycle.py:17–45, 105–168](../../AgroCast/agrocast/autopilot/cycle.py#L105-L168), [pipeline.py:114–135](../../AgroCast/agrocast/serve/pipeline.py#L114-L135), [region.py:14–15](../../AgroCast/agrocast/serve/region.py#L14-L15).

Compose не запускает существующий scheduler. Incremental update не обновляет `strat_snow`, regimes и land/ocean features. `ready.json` с одним `ok` позволяет бесконечно пропускать подготовку без сверки версий/свежести. Monthly cycle пересобирает backtest, но не весь согласованный набор calibrator/stack-артефактов. **Исправление:** явный DAG зависимостей, политики обновления источников, staging-снимок, проверки качества и атомарное продвижение полного model/data release.

### R16 · P1 · Сборка и CI не образуют воспроизводимый release-процесс

[requirements.txt](../../AgroCast/requirements.txt), [app.py:7–30](../../AgroCast/app.py#L7-L30), [ci.yml](../../.github/workflows/ci.yml), [Dockerfile](../../Dockerfile), [docker-compose.yml](../../deploy/docker-compose.yml).

Часть прямых зависимостей задана через `>=`, транзитивного lock с hashes нет, test/dev-группы не выделены. **Проверено:** `check_deps()` считает `scikit-learn` отсутствующим при установленном `sklearn`, поскольку использует имя дистрибутива как имя модуля; launcher пытается устанавливать пакеты при запуске.

Работоспособность native-зависимостей в slim-образе ещё надо проверить сборкой, а не предполагать.

### R18 · P1 · Эксплуатационные и правовые условия выпуска не оформлены

Логи есть, но нет метрик очереди, отказов моделей, возраста predictor frame, договорённых SLO, request/job correlation и проверенных runbook/backup/rollback. Многие исключения ядра молча проглатываются, поэтому частичный прогноз может выглядеть полноценным.

## Как повторить базовые проверки

Из корня репозитория, в отдельной среде:

```bash
python -m venv .venv
.venv/bin/python -m pip install -r AgroCast/requirements.txt pytest pytest-cov httpx
.venv/bin/python -m pip check
cd AgroCast
mkdir -p data/production-audit
COVERAGE_FILE=data/production-audit/.coverage OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 ../.venv/bin/python -m pytest tests -q --cov=agrocast --cov-report=term-missing --durations=10
../.venv/bin/python -m scripts.zarr_freshness
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 ../.venv/bin/python -m scripts.audit_full mini5 --workers 2
```

Команды запускаются отдельно: ожидаемый `exit 1` freshness не должен скрывать остальные результаты. `mini5` удаляет старые `data/audit/points/P*.parquet` и переиспользует precompute-кэш: повторять его следует в чистом рабочем каталоге либо предварительно сохранить нужные результаты полного аудита. Сам этот аудит выполнялся с отсутствовавшим precompute-кэшем.

Диагностические логи сохранены локально в игнорируемом `AgroCast/data/production-audit`; научные выходы `mini5` — в `AgroCast/data/audit`. Они намеренно не добавлены в Git. Зафиксированные выше результаты достаточны для чтения документа без этих локальных файлов.
