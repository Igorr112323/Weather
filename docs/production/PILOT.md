## Действующий scope

AgroCast остаётся исследовательским MVP. Исправление доступа не подтверждает научный навык и не разрешает новые агрорекомендации. Разрешённый набор **новых forecast mode/horizon/season_len по-прежнему пуст**.

| Возможность | Статус |
|---|---|
| Культура | Кукуруза на зерно (`maize`) |
| Регион | Краснодарский край (`krai`), зафиксированные P01–P28 |
| Исходные исторические оценки | Просмотр после личного входа; `unverified`, не основание для агрорешений |
| Свои поля | Чтение по owner; создание/изменение/удаление только operator/admin |
| Справочник | Чтение участниками своей организации; запись только admin |
| Настройки подписок | Только свои, неактивные, без вычислений и отправки |
| Сохранённые jobs в новом SQL-хранилище | Только owner; чтение не подтверждает качество прогноза |
| Пользователи | Управление только admin своей организации; без публичной регистрации |
| Новый forecast, hindcast, region refresh | Отключены для всех ролей, включая admin |
| Активация подписок, агрорекомендации | Отключены |
| Другие регионы/произвольные точки России | Не допущены |
| Старые process-local jobs и registry/crops SQLite | Не подключены к новым аккаунтам автоматически |
| Альтернативный engine API | HTTP 410 на всех маршрутах |

Наличие сетки, модели или положительной старой метрики не означает production-допуска. Исторический scope отчёта — 2005–2024, monthly lead 1 и seasonal lead 1 / три месяца. Каталог P01–P28 закреплён в коде; дополнительные/подменённые точки из артефакта не расширяют HTTP-выдачу.

## Доступ

**HTTP Basic и общий secret file из T01 заменены личными аккаунтами.** Переменные `AGROCAST_PILOT_USER`/`AGROCAST_PILOT_SECRET_FILE` больше не работают как способ входа. Нужны PostgreSQL, миграция и начальный admin, созданный локальной командой оператора.

[Актуальная инструкция настройки и матрица ролей](IDENTITY.md).

- Только HTTPS; cookie — Secure/HttpOnly/SameSite=Lax, Origin/CSRF проверяются сервером.
- Без identity-конфигурации/схемы/БД защищённый запрос получает 503, не анонимный доступ.
- Анонимный запрос к API — 401; недостаточная роль — 403; чужой ресурс — 404.
- Прямой доступ к Uvicorn не обходит аутентификацию. Identity-заголовки, loopback и Basic/Bearer не предоставляют права.
- T04 пропускает operator/admin к валидации тел prepare/refresh: неверный запрос — 422, корректный — всё равно 403; задания не создаются.
- Нет переключателя «включить все прогнозы». Новые неразрешённые маршруты и WebSocket закрыты.

Публичны только `/health/live`, `/api/capabilities` и экран входа с его assets. `/health/live` подтверждает ответ процесса, **не готовность данных и не завершённость настройки аккаунтов**. Диагностический `/api/health` доступен только admin и ещё не заменяет readiness из T07.

## Исторические результаты и UI

Численные исторические ответы содержат `policy_version` и `validation`: `status=unverified`, `production_ready=false`, `agronomic_use_allowed=false`, `coverage_guaranteed=false`. Серверное предупреждение в паспорте видно без JavaScript. Исходные научные артефакты не переписаны.

Главная страница остаётся ограниченным входом в пилот с личной сессией, а не старой картой с доступными расчётами. На `/workspace` доступны безопасные формы собственных полей и справочника. `/report.html?job=<uuid>` показывает только свою сохранённую SQL-запись; ownership проверяется ещё до выдачи HTML. Настройки подписок пока читаются в UI и изменяются через API. Новый расчёт не запускается при просмотре архива.

Ответы имеют `Cache-Control: no-store`, `Vary: Cookie`, `nosniff`, `X-Robots-Tag` и `Referrer-Policy: no-referrer`. T03 добавляет enforced CSP без unsafe-inline/unsafe-eval, локальный Leaflet с SRI и безопасный DOM; детали и ограничения в [BROWSER_SECURITY.md](BROWSER_SECURITY.md).
