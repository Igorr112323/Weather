# Weather

Сезонный агропрогноз **AgroCast** для России: собственные расчёты на открытых
данных, ансамбль из 9 моделей, честный вероятностный прогноз с публичным
реестром навыка.

Продукт: папка [`AgroCast`](AgroCast) — запуск `python app.py` (Python 3.11+),
подробности в [`AgroCast/README_ЗАПУСК.txt`](AgroCast/README_ЗАПУСК.txt).

## Что внутри (коротко)

- **Данные (свои, открытые, без чужих прогнозов):** ERA5-стиль региона,
  SST (OISST), ледовитость, снежный покров (NOAA CDR), стратосфера
  (u10/z50 с 1948), почвенная влага, российские станции.
- **Ансамбль (9 моделей):** климат, аналог, ridge, GBM (LightGBM),
  ridge по суше/океану/**стратосфере**, «глубинный аналог» (состояние
  зимы в пространстве ПСК), SSW-триггер (коллапс полярного вихря).
- **Калибровки:** изотоническая (терцили) + **конформная** (квантили —
  конечновыборочная гарантия покрытия P10–P90 ≈ 80%; проверено в
  проверке прошлого 2004–24: 79–80%, форвард 2025–26: ≥80%).
- **Весовые схемы:** блэнд по RPSS с весами «свежести» (полупериод 5 лет),
  сезонные ворота, shrinkage к климату.
- **Честность:** walk-forward 2004–2024 (21 год) без подглядывания
  (leave-one-year-out), данные с 1948 (стратосфера) / 1976 (SST) / 1979 (регион),
  **реестр доверия** — каждый прогноз с SHA-256-хэшем входов,
  RPSS/попадания/ECE/покрытие — в каждом отчёте.
- **Отчёты для фермера:** «Главное — что делать» (топ-3), декады, полив в
  м³/га, САТ, фено-календарь, риски в ₽, годы-аналоги с урожаем,
  «почему такой прогноз» (драйверы), паспорт доверия, почтовый дайджест.
- **Культура — кукуруза на зерно** (продукт сфокусирован на одной культуре):
  параметры не «из головы» — по агроисточникам: САТ по группам спелости
  (2200–2800°, порог 10°C; kccc.ru, rosgibrid.ru), морозостойкость по фазам
  (всходы до −2°C, гибель при −3°C; генеративные органы до −1°C, початки
  молочно-восковой спелости до −4°C), окно сева Краснодарского края
  20–30 апреля — 15 мая при прогреве почвы 10–12°C (rosagrochim.ru).
- **Цены — биржевые, ежедневное обновление:** фьючерс на кукурузу CBOT
  (Chicago Board of Trade) в USD × спотовый USD/RUB → ₽/т (модуль
  `agrocast/market`); офлайн — последний кэш/seed со значением даты,
  устаревшая цена (>3 дней) помечается в отчёте.

## Проверенный навык (walk-forward 2005–2024, 50 точек, 48 000 верификаций)

- **Температура (t2m)** — стабильный навык: сезонный RPSS ≈ +0.25 (hit ≈ 64%),
  месячный ≈ +0.14 (hit ≈ 52%). Часть навыка даёт адаптивная климатология
  (базлайн ≈ +0.21 сезонный), ансамбль добавляет к ней ≈ +0.05…+0.07.
- **Осадки (tp)** — навык на уровне шума: лучший ансамбль ≈ +0.01…+0.04
  RPSS (базлайн климатологии ≈ −0.04). В отчётах осадки помечены честно:
  «навык не подтверждён — уровень климатологии». Рекомендации по поливу
  строятся на дефиците ET0 (зависит от температуры, где навык есть), а не на
  прогнозе осадков.
- **Метод:** путь «проверки прошлого» = путь LIVE-прогноза (leave-one-year-out
  ансамбль → нейроядро → терцильная калибровка). Вес нейроядра α подбирается
  на 2004–2014 и берётся только если строго улучшает RPS на валидации
  2015–2024 (сейчас: 0.0/0.0/0.2/0.0). Терцильная калибровка применяется
  только если улучшает RPS на последних 5 годах истории (сезонные осадки —
  отключена). Аудит: `AgroCast/scripts/audit_full.py`, A/B:
  `AgroCast/scripts/ab_skill.py`, пересборка стека: `AgroCast/scripts/refit_stack.py`.

## CI, деплой, мониторинг

- **CI (GitHub Actions):** на каждый push/PR — `pytest` + **мини-аудит на 5
  точках** (реальный recompute: precompute → 5 точек × 960 верификаций →
  отчёт → контроль: конформальное покрытие P10–P90 72–85%, RPSS/ECE/hit
  сезонного t2m в пределах нормы). Падение любого чек-а — красный билд.
  Воркфлоу: `.github/workflows/ci.yml`.
- **Монитор свежести zarr:** еженедельный scheduled-run
  (`.github/workflows/freshness.yml`) + вручную (`workflow_dispatch`).
  `AgroCast/scripts/zarr_freshness.py` проверяет последний день данных в
  каждом zarr-сторе против норматива с учётом латентности источника:
  daily_region 14 дней (требование «>2 недель»), почва/снег 60, SST 120
  (OISST приходит с 2–3-месячной задержкой), сезонные 90, режимы 365.
  Превышение — **АЛЕРТ** (exit 1, красный чек → уведомление GitHub).
  Локально: `cd AgroCast && python -m scripts.zarr_freshness`.
- **Docker:** `Dockerfile` в корне (python 3.11-slim, uvicorn, healthcheck
  по `/api/health`, логи в том `agrocast-data`).
  Сборка: `docker build -t agrocast .`
- **HTTPS:** `deploy/docker-compose.yml` + `deploy/Caddyfile` — Caddy
  ставит Let's Encrypt-сертификат автоматически на домен
  `AGROCAST_DOMAIN` (переменная окружения), TLS терминируется на Caddy,
  приложение слушает 8501 внутри сети:
  `cd deploy && AGROCAST_DOMAIN=agrocast.example.com docker compose up -d`.
  Локальный запуск без домена: `python app.py` (http://127.0.0.1:8501).
- **Логи:** приложение пишет в stdout (в Docker — в лог-драйвер) и в
  `AgroCast/data/logs/app.log` (ротация 5 МБ × 3). Уровень —
  `AGROCAST_LOG_LEVEL` (INFO по умолчанию). Логгируется: старт, каждый
  запрос (метод, путь, статус, время ответа), запуск/ошибки расчётных
  джобов, подписки.

## Структура

```
.github/workflows/    # ci.yml (pytest + мини-аудит 5 точек), freshness.yml (свежесть zarr)
Dockerfile            # образ приложения
deploy/               # docker-compose.yml + Caddyfile (авто-HTTPS)
AgroCast/
├── app.py                 # лаунчер: ставит deps, поднимает сервер, открывает карту
├── static/                # карта + отчёт (Leaflet)
├── agrocast/              # 13 подпакетов: ingest → features → models → blend
│   │                      #   → backtest → skill(ledger) → serve
│   ├── models/            # 9 моделей ансамбля (вкл. deep_analog, ssw)
│   ├── blend/             # блэнд по RPSS, изотоника, конформная калибровка
│   ├── backtest/          # walk-forward-движок, метрики (RPS/RPSS/ECE)
│   ├── skill/             # реестр доверия (trust ledger)
│   └── serve/             # FastAPI: продукт (карта) + API + почта
├── world/                 # данные (zarr) + артефакты обучения
├── scripts/               # refit_world.py, ab_skill.py, refit_stack.py, audit_full.py
└── tests/                 # pytest
```
