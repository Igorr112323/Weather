# Weather

Исследовательская система сезонного агропрогноза **AgroCast**: собственные
расчёты на открытых данных и экспериментальный ансамбль моделей.

Код: [`AgroCast`](AgroCast), Python 3.11+. Текущий HTTP-режим — **закрытый
пилот с личными аккаунтами; новые прогнозы отключены**.
[Настройка входа, PostgreSQL и запуск](docs/production/IDENTITY.md).

## Готовность к продакшену

По результатам аудита от **2026-09-05** проект пока не готов к открытому
промышленному использованию. На исходном срезе тесты и мини-аудит проходили, но найдены
блокирующие проблемы безопасности, сохранности состояния, свежести данных
и методики проверки прогнозного навыка. Приведённые ниже оценки навыка и
заявления о гарантиях требуют повторной проверки; не следует считать их
независимо подтверждёнными production-характеристиками.

- [План работ: этапы, приоритеты, зависимости и критерии приёмки](docs/production/PLAN.md).
- [Технический аудит с результатами проверок и ссылками на код](docs/production/AUDIT.md).
- [Чек-лист выпуска и эксплуатационных проверок](docs/production/RELEASE_CHECKLIST.md).

**T01–T05 реализованы и локально проверены:** ограниченный scope, личные
аккаунты, роли reader/operator/admin, серверные сессии и PostgreSQL.
Добавлены безопасный DOM, enforced CSP, локальный Leaflet, типизированный
HTTP-контракт, параметризованный региональный кэш, единые settings, явная
app factory, read-only bundle и проверяемый перенос/backup/restore состояния.
Свои поля и неактивные настройки подписок доступны по правам; справочник —
только внутри организации. Новый forecast, hindcast и агрорекомендации
остаются отключёнными даже для admin. Собственные поля и справочник доступны
на `/workspace`, свои сохранённые записи — через защищённый просмотр отчёта.

Общий пароль T01 больше не предоставляет доступ. Нужны PostgreSQL, миграция
и аккаунт, созданный администратором. Неправильная конфигурация или неготовая
БД останавливают startup с безопасной причиной; без сессии работающий API
отвечает 401. Docker build/recreate ещё не проверены; production-релиз не разрешён.

## Что внутри исследовательского ядра

- **Данные (свои, открытые, без чужих прогнозов):** ERA5-стиль региона,
  SST (OISST), ледовитость, снежный покров (NOAA CDR), стратосфера
  (u10/z50 с 1948), почвенная влага, российские станции.
- **Ансамбль (9 моделей):** климат, аналог, ridge, GBM (LightGBM),
  ridge по суше/океану/**стратосфере**, «глубинный аналог» (состояние
  зимы в пространстве ПСК), SSW-триггер (коллапс полярного вихря).
  К сезонным осадкам добавляются **2 физических модели** (DJF/MAM) на
  драйверах океанских осцилляций (PDO, ENSO), скандинавском/полярном
  давлении и региональном снеге; без подтверждённого навыка блэнд
  сводит их к нулю (JJA/SON сигнал не подтверждён — климатология).
- **Калибровки:** изотоническая (терцили) + **конформная** (квантили —
  конечновыборочная гарантия покрытия P10–P90 ≈ 80%; проверено в
  проверке прошлого 2004–24: 79–80%, форвард 2025–26: ≥80%).
- **Весовые схемы:** блэнд по RPSS с весами «свежести» (полупериод 5 лет),
  сезонные ворота, shrinkage к климату.
- **Честность:** walk-forward 2004–2024 (21 год) без подглядывания
  (leave-one-year-out), данные с 1948 (стратосфера) / 1976 (SST) / 1979 (регион),
  **реестр доверия** — каждый прогноз с SHA-256-хэшем входов,
  RPSS/попадания/ECE/покрытие — в каждом отчёте.
- **Регион (Фаза 3):** сетка КРА из **28 ячеек 0.5°** (фильтр покрытия данных
  ≥90%) + **обыкновенный кринг**: экспоненциальная вариограмма
  (подбор nugget/sill/range), детрендинг плоскостью lat/lon, IDW-фолбэк
  при вырожденной ковариации. Аудит сетки: `python -m scripts.audit_full grid`
  (28 точек, 26 880 верификаций). **В продукте:** API `/api/region/{grid,skill,
  field,refresh}` + карта (кринг-поле терцилей 0.25°, 28 точек, легенда),
  «Рассчитать поле» — фоновый джоб на 28 точек (~4–5 мин); честная пометка
  о неподтверждённом навыке осадков — в UI и в артефакте поля.
  CLI: `python -m scripts.krig_demo`.
- **Отчёты для фермера:** «Главное — что делать» (топ-3), декады, полив в
  м³/га, САТ, фено-календарь, риски в ₽, годы-аналоги с урожаем,
  «почему такой прогноз» (драйверы), паспорт доверия, почтовый дайджест.
- **Культура — кукуруза на зерно** (продукт сфокусирован на одной культуре):
  параметры не «из головы» — по агроисточникам: САТ по группам спелости
  (2200–2800°, порог 10°C; kccc.ru, rosgibrid.ru), морозостойкость по фазам
  (всходы до −2°C, гибель при −3°C; генеративные органы до −1°C, початки
  молочно-восковой спелости до −4°C), окно сева Краснодарского края
  20–30 апреля — 15 мая при прогреве почвы 10–12°C (rosagrochim.ru).
- **Цены — биржевые, ежедневное обновление:** фьючерс на кукурузу CBOT
  (Chicago Board of Trade) в USD × спотовый USD/RUB → ₽/т (модуль
  `agrocast/market`); офлайн — последний кэш/seed со значением даты,
  устаревшая цена (>3 дней) помечается в отчёте.

## Исходные оценки навыка (2005–2024, 50 точек, 48 000 верификаций)

- **Температура (t2m)** — стабильный навык: сезонный RPSS ≈ +0.25 (hit ≈ 64%),
  месячный ≈ +0.14 (hit ≈ 52%). Часть навыка даёт адаптивная климатология
  (базлайн ≈ +0.21 сезонный), ансамбль добавляет к ней ≈ +0.05…+0.07.
- **Осадки (tp)** — на ключевой точке (45.0N, 39.5E), сезонный режим,
  2004–2024: физическая модель зимы (DJF) в одиночку +0.11 (walk-forward;
  фичи отбирались без подглядывания: на выдержке 2011–24 — тоже +0.11),
  финальный блэнд **DJF +0.04**; MAM/JJA/SON — уровень климатологии
  (−0.03/−0.01/−0.00 против базлайна −0.05/0/0). В отчётах осадки
  помечены честно: за пределами DJF «навык не подтверждён». Нейроядро
  для tp запрещено конструктивно (α≡0.0). Рекомендации по поливу
  строятся на дефиците ET0 (зависит от температуры, где навык есть), а не на
  прогнозе осадков.
- **Метод:** путь «проверки прошлого» = путь LIVE-прогноза (leave-one-year-out
  ансамбль → нейроядро → терцильная калибровка). Вес нейроядра α подбирается
  на 2004–2014 и берётся только если строго улучшает RPS на валидации
  2015–2024 (сейчас: 0.2/0.0/0.2/0.0; для tp всегда 0.0). Терцильная
  калибровка применяется
  только если улучшает RPS на последних 5 годах истории (сезонные осадки —
  отключена). Аудит: `AgroCast/scripts/audit_full.py`, A/B:
  `AgroCast/scripts/ab_skill.py`, пересборка стека: `AgroCast/scripts/refit_stack.py`.

### Сетка КРА: 28 точек, 26 880 верификаций (Фаза 3, шаг 1)

- Аудит по сетке Краснодарского края — 28 ячеек 0.5° (44–46.5°N, 37–40.5°E,
  артефакт `world/artifacts/krai_grid.json`), 20 лет (2005–2024), 2 режима:
  `cd AgroCast && python -m scripts.audit_full grid`. Тот же путь «проверки
  прошлого», что и в 50-точечном аудите бокса.
- **Температура (t2m)** — сезонный RPSS **+0.254 на всех 28 точках** (hit 63%;
  по сезонам: зима +15%, весна +20%, лето +40%, осень +25%); месячный
  +0.118…+0.138 — положительный на 28/28 точек. Сезонные метрики едины по
  точкам (ансамбль P один на бокс — так устроен продукт), месячные
  различаются за счёт пер-точечного NN-mix.
- **Осадки (tp)** — навык не подтверждён ни на одной точке (сезонный RPSS
  −0.06, месячный −0.02): в отчётах честно помечено «навык не подтверждён —
  уровень климатологии». Конформальное покрытие P10–P90 — 79–80% (цель ≈80%).

## Регион: сетка КРА, кринг и аудит 28 точек (Фаза 3, шаг 1)

- **Сетка КРА** (`agrocast/region/grid.py`): ячейки 0.5° по Краснодарскому
  краю (44–46.5°N, 37–40.5°E) — 35 кандидатов, фильтр покрытия данных ≥90%
  по t2m и tp (1979–2026, тот же критерий, что в `PointDataset`) →
  **28 доступных ячеек** (прибрежные с неполными рядами отброшены).
  Набор зафиксирован артефактом `AgroCast/world/artifacts/krai_grid.json`
  (P01–P28, с севера на юг); пересборка — `python -m scripts.audit_full grid`
  или вручную через `krai_cells(store)` + `save_grid(cells)`.
- **Обыкновенный кринг** (`agrocast/region/kriging.py`): экспоненциальная
  вариограмма γ(h) = nugget + psill·(1 − exp(−h/range)) с подбором параметров
  по эмпирической вариограмме (расстояния — гаверсинусовы, км),
  детрендинг плоскостью lat/lon, система ОК с множителем Лагранжа (Σw = 1),
  дисперсия кринга в ответе. Фолбэк на IDW при вырожденной ковариационной
  матрице (дубли точек, <3 точек) — честно помечен в результате.
  Покрыто тестами: +11 (итого **56 passed**).
- **Аудит 28 точек** (`cd AgroCast && python -m scripts.audit_full grid`,
  20 лет 2005–2024, 2 режима, **26 880 верификаций**, ≈20 мин на 2 ядрах):
  тот же путь «проверки прошлого», что и в 50-точечном аудите бокса.
  Сезонный t2m — **RPSS +0.254 на всех 28 точках**, hit 63% (по сезонам:
  зима +15%, весна +20%, лето +40%, осень +25%); месячный t2m
  +0.118…+0.138 — положительный на 28/28 точек. Сезонные метрики едины
  по точкам (ансамбль P один на бокс — так устроен продукт), месячные
  различаются за счёт пер-точечного NN-mix. **Осадки: навык не подтверждён
  ни на одной точке** (сезонный RPSS −0.06, месячный −0.02) — в отчёте
  честно помечено «навык не подтверждён — уровень климатологии».
  Конформальное покрытие P10–P90 **79%** (цель ≈80%). Отчёт:
  `AgroCast/data/audit/audit_report_grid.md` + `grid_summary.json`.
- **Кринг-демо** (`cd AgroCast && python -m scripts.krig_demo`): LIVE-прогноз
  всех 28 точек (полный путь продукта, сезонный режим, старт 2026-10) →
  кринг-поле терцилей **осадков** на сетке **0.25°** (140 ячеек) →
  `AgroCast/data/audit/krig_demo_tp.json` (точки + поля below/normal/above),
  ~3 мин на 2 ядрах. В JSON честная пометка: навык осадков на сетке КРА
  не подтверждён — поле демонстрирует связность прогноза продукта,
  а не подтверждённый навык.

## CI, деплой, мониторинг

- **CI (GitHub Actions):** на push в `main` и pull request — `pytest` + **мини-аудит на 5
  точках** (реальный recompute: precompute → 5 точек × 960 верификаций →
  отчёт → контроль: конформальное покрытие P10–P90 72–85%, RPSS/ECE/hit
  сезонного t2m в пределах нормы). Падение любого чек-а — красный билд.
  Воркфлоу: `.github/workflows/ci.yml`.
- **Монитор свежести zarr:** еженедельный scheduled-run
  (`.github/workflows/freshness.yml`) + вручную (`workflow_dispatch`).
  `AgroCast/scripts/zarr_freshness.py` проверяет последний день данных в
  каждом zarr-сторе против норматива с учётом латентности источника:
  daily_region 14 дней (требование «>2 недель»), почва/снег 60, SST 120
  (OISST приходит с 2–3-месячной задержкой), сезонные 90, режимы 365.
  Превышение — **АЛЕРТ** (exit 1, красный чек → уведомление GitHub).
  Локально: `cd AgroCast && python -m scripts.zarr_freshness`.
- **Docker:** `Dockerfile` в корне (python 3.11-slim, uvicorn, healthcheck
  по `/health/live`, только liveness, логи в том `agrocast-data`).
  Сборка: `docker build -t agrocast .`
- **HTTPS:** `deploy/docker-compose.yml` + `deploy/Caddyfile` — Caddy
  ставит Let's Encrypt-сертификат автоматически на домен
  `AGROCAST_DOMAIN` (переменная окружения), TLS терминируется на Caddy,
  приложение слушает 8501 внутри сети. Обязательны файлы секретов PostgreSQL:
  [инструкция для локального запуска и Compose](docs/production/IDENTITY.md).
  В T02 добавлены PostgreSQL и migration job. Docker/TLS deployment ещё не проверялся; healthcheck не заменяет
  readiness, backup и остальные release gates.
- **Логи:** приложение пишет в stdout (в Docker — в лог-драйвер) и в
  `AgroCast/data/logs/app.log` (ротация 5 МБ × 3). Уровень —
  `AGROCAST_LOG_LEVEL` (INFO по умолчанию). Логгируется: старт, каждый
  запрос (метод, путь, статус, время ответа), запуск/ошибки расчётных
  джобов, подписки.
