Измерено 2026-09-07 стендом `python -m scripts.perf_report` (скрипт в репозитории,
воспроизводим). **Стенд — CI-песочница (Linux x86_64, 2 CPU, Python 3.11), это НЕ
пользовательское железо**; SLO раздела 6 PLAN утверждались для серверного пилота и
не переносятся молча на десктоп — ниже фактические числа, не цели.

| Сценарий | Стена | CPU | Peak RSS |

| Тот же запрос, тёплый кэш (hit) | ~0 с | ~0 с | — |
| Поле КРА (28 ячеек 0.5°, 2 worker слота) | 296 с | параллельно в пуле (счётчик процесса main не показывает) | ~831 МБ |

Потребление памяти ограничено одной пиковой точкой ~0.8 ГБ (один расчёт);
поле на двух слотах остаётся в том же порядке — worker-пул переиспользует процесс.

## Что нашёл замер (и починил)

Повторный запрос с готовым результатом **не попадал в кэш**: envelope-отпечаток
`payload_sha256` считался до нормализации JSON, а блок заморозков
`p_frost_day_by_month` имел целочисленные ключи месяцев — каноническая
сериализация сортировала их числово, а после парсинга ключи-строки сортируются
лексикографически, round-trip не идемпотентен, и кэш-ридер отклонял собственный
конверт. Исправлено в двух местах: `jsoncodec.canonical_json` нормализует ключи
словарей к строкам и отклоняет коллизии нормализации (дубликаты после
строкования), а frost отдаёт строковые ключи. Закрыто тестом идемпотентности
round-trip и тёплым прогоном выше (hit, ~0 с).

## Ограничения и следующие шаги

- p50/p95 и «20 минут под 10 RPS» из раздела 6 — прогон на целевом железе
  пользователя не выполнялся; для десктопа нагрузка по определению однопользовательская,
  но цифры p50/p95 обязаны быть измерены на согласованном стенде перед утверждением SLO
  (часть T24 release review);
- холодный старт с докачкой наблюдений для новой точки включает сеть (2–6 минут
  на скачивание годовых рядов CPC) — это ожидание источника, в бюджет расчёта не входит,
  публикуется логом `ensure_point`;
- отчёт CPU для поля неполон по конструкции стенда (дочерние процессы пула) — при
  утверждении SLO заменить на системный замер (perf/cgroup).

Воспроизвести: `cd AgroCast && python -m scripts.perf_report [world_dir state_dir]`.
