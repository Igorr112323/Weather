# Десктоп-версия AgroCast (контур D)

Решение владельца от 2026-09-06: продукт становится **самостоятельным приложением**, а не
страницей в браузере. Человек скачивает установщик, открывает окно и работает; приём через
браузерный веб-пилот не меняется (там остаются HTTPS, аккаунты, CSRF и закрытый научный
допуск). Оба контура используют одно ядро `agrocast`.

## Что видит пользователь

Один экран, три блока сверху вниз:

1. **Прогноз** — выбор точки (28 проверочных точек Краснодарского края) и месяца выпуска,
   одна большая кнопка. Результат — вероятности tercile по температуре и осадкам
   («выше/около/ниже нормы») плюс медиана осадков; полные данные в раскрывающемся JSON.
2. **Данные, из которых считается прогноз** — три карточки со списком реальных файлов и дат:
   локальный набор моделей (`world`: количество, суммарный размер, манифест-конфигурация,
   отпечаток release), скачанные суточные наблюдения (`state/compute`) и кэш результатов
   (`results-v1`, с датой `created_at` из конверта кэша — не mtime). Кнопка «Обновить».
3. **Как это работает** — четыре пункта, включая путь данных и где живёт состояние.

При первом расчёте новой точки приложение докачивает суточные наблюдения CPC (обычно 2–6
минут, один раз на точку); дальше всё офлайн и мгновенно из кэша. В интернет не уходит
ничего, кроме этой докачки; карты нет по умолчанию — координаты не передаются третьим
сторонам.

## Архитектура

- Окно: PySide6 `QWebEngineView` (встроенный Chromium — одинаковый рендеринг на Windows,
  macOS и Linux). Заголовок окна «AgroCast — локальные прогнозы».
- Сервер: тот же FastAPI `create_app`, запущенный в потоке того же процесса на
  `127.0.0.1:<случайный порт>` (предзакрытый сокет — без гонок за порт). Наружу порт не
  публикуется: другие локальные пользователи и сеть доступа не имеют.
- Флаг `AGROCAST_DESKTOP` / `RuntimeSettings.desktop_mode`:
  - AccessGuard в desktop-ветке пропускает запросы как локального администратора (синтетический
    `Principal`, создаётся lifespan'ом; таблицы `organizations`/`users` провижинятся одним
    стабильным uuid5-идентификатором) — без сессий, cookies и CSRF, которые на localhost
    не имеют смысла;
  - вход в веб-механизмы закрыт явно: `/api/auth/*`, `/api/admin/*`, `/api/prepare`,
    `/api/region/refresh` дают `403 desktop_operation_disabled`; очередь T06 в desktop не
    используется и приём её остаётся выключенным;
  - `GET /` отдаёт `desktop.html` вместо страницы пилота; `/api/capabilities` сообщает
    `operations.local_mode = true`.
- Состояние: `~/.agrocast` (переопределяется `AGROCAST_DESKTOP_HOME`): `agrocast.db`
  (SQLite WAL + foreign keys), `compute/` (наблюдения и точки), `results-v1/` (кэш),
  `desktop-releases.json` (права 0600).
- Local forecast: `POST /api/local/forecast` считает синхронно в потоке пула тем же
  кодом `ensure_point` + `forecast_point`, что и worker очереди; идентичность результата —
  `ResultIdentity.point` со snapshot'ом world-конфигурации и очереди, то есть запись в кэш
  полностью совместима с web-путём T04/T06. `GET /api/local/inputs` — экран данных.
  Вне desktop-режима оба эндпоинта отдают `403 desktop_only` — в веб-контуре их нет.
- Release-отпечатки desktop'а вычисляются честно из бандла (хэш `world/ready.json` — или
  списка файлов — как `data_release`, `config.json` как `model_release`, `CONTRACT_VERSION`
  как `application_release`) и фиксируются в `desktop-releases.json` при первом запуске,
  чтобы последующие кэш-ключи были стабильны.

## Сборка и доставка

- Зависимости: `AgroCast/requirements-desktop.txt` (ядро + PySide6 + PyInstaller).
- Спецификация: `AgroCast/desktop/AgroCast.spec` — onedir-сборка (обязательно для
  QtWebEngine), внутрь укладываются `static/`, `world/` (≈60 МБ бандла) и `migrations/`;
  `psycopg`/Qt-конкуренты исключены. Итог: папка `dist/AgroCast` с бинарником; для Windows
  это `AgroCast.exe` в той же папке (рядом — Qt/Chromium рантайм; запускать ярлыком).
- Иконка: `desktop/icon-source.png` (источник), из него собираются `desktop/agrocast.ico`
  (Windows), `desktop/agrocast.icns` (macOS) — подставляются в EXE через `icon=` в спеке, и
  `static/agrocast.png` — иконка окна Qt (`setWindowIcon`), вкладок и значок приложения на
  Linux. Пересборка форматов: `python -c "...PIL resize/save..."` — размеры ico 16–256; либо
  `iconutil` на macOS из `iconset`.
- Запуск из исходников (для разработчиков): `python -m agrocast.desktop`. Без установленного
  PySide6 сервер всё равно поднимается и пишет URL в stderr — полезная деградация и база для
  headless-смоуков.
- CI: `.github/workflows/desktop-builds.yml` собирает матрицу windows/ubuntu/macos,
  прогоняет `tests/test_desktop.py` + `test_runtime_settings.py` и headless-смоук
  встроенного сервера, загружает три артефакта. Локальная сборка: `desktop/build.sh`.
- Установка: скачанный архив артефакта распаковать и запустить `AgroCast(.exe)`; установки «в
  систему» нет. Подписи/нотаризации пока нет — Windows может показать SmartScreen, macOS —
  Gatekeeper (правый клик → «Открыть»); это зафиксировано как известный лимит до этапа
  кода-подписи.

## Проверки по операционным системам

CI `desktop-builds` (матрица windows/ubuntu/macos: тесты + смоук встроенного сервера +
PyInstaller + артефакты):

| ОС | Тесты | Смоук сервера | Сборка PyInstaller |
|----|-------|---------------|--------------------|
| ubuntu-22.04 | зелёный | зелёный | зелёный, артефакт загружен |
| macos-14 | зелёный (после `brew install libomp` — lightgbm ищет OpenMP) | зелёный | зелёный, артефакт загружен |
| windows-latest | красным был `UnicodeDecodeError` из-за кодировки cp1251 в тестовом подпроцессе и `fsync` каталога; оба исправлены в коде (явный UTF-8 в подпроцессе, пропуск directory-fsync не-POSIX), проверка перезапуском CI ещё не подтверждена | — | — |

Четвёртый дефект переносимости исправлен в лаунчере: uvicorn при `fd=` сам вызывает
`socket.fromfd(..., socket.AF_UNIX, ...)`, чего на Windows нет; теперь лаунчер передаёт
uvicorn готовый сокет, продублированный с явным `AF_INET` (`sockets=[...]`) — одинаково на
всех трёх ОС.

Три кросс-платформенных дефекта, найденных именно CI, а не локально: `os.fsync` на
дескрипторе каталога недопустим на Windows (теперь `fsync_directory` — no-op вне POSIX),
чтение снапшота подпроцессом без явной кодировки ломалось на cp1251, и бит 0600 на Windows
не воспроизводим (проверка режима обёрнута в `os.name == "posix"`). Флаг POSIX-режима у
release-манифеста в `test_desktop.py` — то же ограничение ОС, а не продукта.

## Приёмка и честные границы

Покрыто тестами: провижининг локального владельца, страница без логина, `local_mode` в
capabilities, явное 403 для auth/admin/очереди, экран данных (файлы бандла, дубликаты
query-параметров → 422, content-type → 415), полный локальный расчёт с кэшем (второй запрос
`cached=true`, кэш-файл ровно один, release-манифест 0600), отсутствие записей в очередях,
запрет тех же эндпоинтов в веб-режиме. Реальный научный расчёт в тесте выполняется из
read-only bundle без сети.

Не проверено здесь и честно помечено: подлинность оконного рендера на Windows/macOS (нужен
ручной прогон артефактов CI), инсталляторы (.exe-установщик, .dmg, AppImage — сейчас это
папка-артефакт), автообновления, кодовая подпись, перенос состояния между машинами. Научные
результаты desktop-версии не публикуются и не проходят пилотные release gates; это инструмент
личного просмотра на своей машине.
