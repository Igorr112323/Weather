# Метрики навыка и калибровка (T11)

Единый источник определений — `agrocast/backtest/metrics.py`; все отчёты
(engine `skill_map`, walk-forward ledger, пространственный артефакт
`grid-skill-v2`, аудит `audit_full`) считают метрики одними и теми же
функциями. Раздельные локальные формулы удалены; тест
`tests/test_metrics_t11.py` сверяет числовые значения между всеми
отчётными путями на одном контрольном примере.

## Определения

- **RPS (строка).** `rps_rows(probs, obs)`: Σ_k (F_k − O_k)², где F —
  кумулятив прогнозных вероятностей терцилей, O — кумулятив one-hot
  наблюдения. Чем меньше, тем лучше.
- **Бейзлайн (согласовано 2026-09-06, пользователь).** Эмпирическая
  терцильная климатология по target-месяцу внутри проверочного окна с
  сглаживанием +1 на класс: `tercile_baseline(obs, months, prior=1)`. В
  пространственном отчёте она строится по локальным наблюдениям каждой
  ячейки; в точечных отчётах — по выборке данного среза. Равномерный
  климат 1/3 оставлен только как явный выбор `baseline="uniform"` для
  исторической сопоставимости; по умолчанию он запрещён, поскольку
  завышает RPSS на скошенных распределениях.
- **RPSS.** `1 − mean RPS_model / mean RPS_baseline` (отношение средних,
  не среднее отношений). Строковое значение для bootstrap
  `rpss_i = 1 − rps_i / mean RPS_baseline` — линейно, поэтому среднее по
  блокам совпадает с агрегатом.
- **Hit.** `argmax(probs) == obs`. Hit-подмножество `hit_conf` сохраняется
  в ledger как описательная статистика, не как метрика продвижения.
- **ECE.** Явные bins: равномерная сетка [0,1] с `ECE_BINS=10`, границы и
  числа строк в bin публикуются (`edges`, `bin_counts`); bin с <5
  строками пропускается. `top_label`: взвешенное |средняя p доминирующего
  класса − частота попадания|. `classwise`: то же, усреднённое по классам
  0..2. Оба значения публикуются во всех отчётах; контрольный
  идеально-калиброванный выборка (категориальные исходы из самих P,
  n=60k) даёт |ECE| < 0.015 и одинаковые числа во всех отчётных путях
  (тест).
- **Покрытие (coverage).** Доля наблюдений в интервале
  `[mu + sd·q10', mu + sd·q90']`. Публикуются: n, доля, Wilson-95 CI
  (`wilson_interval`), средняя ширина в z-единицах (`width80_z` /
  `mean_width_z`) и размер fit-окна, исключённого из оценки.

## Conformal-интервалы: предпосылки и поправки

Split-конформная схема сдвигает квантили на эмпирические квантили
остатков `obs − q_L`. Коррекция конечной выборки: нижний уровень берётся
индексом `floor((n+1)L) − 1`, верхний — `ceil((n+1)L) − 1` (интервал
консервативно расширяется при малом n). Гарантия покрытия —
**условная**, требует обменимости пар (score, точка проверки). В
прогнозном временном ряду с перекрывающимися сезонными окнами и
климатологической нормировкой обменимость выполняется лишь
приближённо, поэтому сервис **не обещает безусловных 80%**: формулировка
«гарантированное покрытие» исключена из кода и доков; в ответах и
артефактах покрытие подаётся как эмпирика с CI и шириной.

## Независимость оценки (fit / calibration / test)

- Официальный навык — walk-forward ledger (T08): калибраторы фолда
  подгоняются строго на записях до фолда; интервалы и метрики фолда не
  пересекаются с его fit-окном.
- Conformal-артефакт хранит `fit_years` (отпечаток лет проверки,
  использованных при подгонке). `coverage80` с `require_out_of_fit=True`
  отказывается считать покрытие на строках из fit-окна
  (`ValueError: coverage измеряется только вне fit/calibration`).
- Пространственный артефакт (`grid-skill-v2`): при наличии конформных и
  p-калибровочных артефактов для мода/переменной строки их `fit_years`
  исключаются из метрик; в `combos[*]["fit_exclusion"]` публикуются
  источник и число исключённых строк. Для legacy-артефактов бандла без
  `fit_years` исключение невозможно — это честно помечается
  `source="none"`, и такой coverage не используется для продвижения.

## Порог продвижения (согласовано до итогового расчёта, 2026-09-06)

Навык переменной в связке (mode, lead) объявляется **подтверждённым**,
если выполняются оба условия:

1. `RPSS > 0` (точечная оценка лучше локального эмпирического бейзлайна);
2. нижняя граница 95% moving-block bootstrap CI (блок 12 мес. для
   monthly, 6 мес. для seasonal, пространственно-усреднённые строки)
   строго больше 0.

Порог зафиксирован в коде как `promotion_decision` и
`PROMOTION_RULE`, в него не входит «сила» уровня (0.05-era гейт аудита
отменён как несогласованный с этим правилом); минимальные пороги
уверенности витрины (`CONFIDENCE_LOW=0.02`, `CONFIDENCE_MEDIUM=0.06`)
остаются описательными уровнями `confidence` и на продвижение не влияют.
Порог не понижается под полученные результаты; при невыполнении навык
не публикуется как подтверждённый, а scope сужается.

## Что публикуется в отчётах

Во всех отчётах рядом с метрикой обязана стоять выборка и блоки:
`n_rows`/`n`, `n_periods`, `n_time_blocks`, `n_spatial_blocks`,
`block_len_months`, `method`, `baseline`, `evaluation`,
`ece_definition`, `rpss_ci95_time`, `coverage` с `wilson95` и шириной,
`skill_promoted` с `promotion_rule`, `fit_exclusion`.
